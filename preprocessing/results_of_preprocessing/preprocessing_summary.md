## 2. Duplicate Removal

**Collisions:** Full row deduplication → then deduplication on `accident_index` (primary key). 
Any collision record appearing more than once with the same index is reduced to the first occurrence.

**Vehicles / Casualties:** Full row deduplication applied. No primary key deduplication (composite key used instead).

> Result: Typically 0–5 duplicate collisions; vehicles/casualties may have hundreds of exact-duplicate rows from source formatting artifacts.

---

## 3. Null / Missing Value Handling

The STATS19 dataset uses domain-specific sentinel codes to represent 'unknown' rather than true `NULL`.

| Sentinel Type | Columns Affected | Action |
|---|---|---|
| `-1` (numeric missing) | All numeric columns | Converted to `NaN` |
| `9`, `99` (domain unknown) | weather, road surface, lighting, junction, etc. | Converted to `NaN` |
| String `'NULL'`, `'NaN'`, `''` | All string-parsed columns | Converted to `NaN` |
| `3` (unallocated area) | `urban_or_rural_area` | Converted to `NaN` |
| `15` (not known) | `journey_purpose_of_driver` | Converted to `NaN` |

After conversion, no imputation is applied to the core collision table — null rows are retained with the `NaN` sentinel for downstream analytical purposes.

---

## 4. Date & Time Standardization

- `accident_date`: Parsed from `DD/MM/YYYY` → `YYYY-MM-DD` (ISO 8601). Invalid dates set to `NaN`.
- `time`: Validated against `HH:MM` pattern. Single-digit hours zero-padded (`8:30` → `08:30`). Invalid strings set to `NaN`.

---

## 5. Geospatial Validation

- `latitude` / `longitude` validated against UK bounding box.
- Records outside bounds have `has_valid_coords = False`.
- BNG (British National Grid) Easting/Northing computed for valid coordinates — used by DBSCAN spatial clustering.

---

## 6. Feature Engineering

| Feature | Derivation |
|---|---|
| `time_period` | Hour → Morning Peak / Daytime / Evening Peak / Evening / Night |
| `day_of_week_name` | `day_of_week` integer → Monday–Sunday string |
| `is_severe` | `accident_severity` ∈ {1 (Fatal), 2 (Serious)} → 1; else 0 |
| `involves_motorcycle` | Any vehicle in accident is type motorcycle |
| `involves_hgv` | Any vehicle is HGV type |
| `involves_cyclist` | Any vehicle is pedal cyclist |
| `month` | Extracted from `accident_date` |
| `hour` | Extracted from `time` |
| `is_weekend` | `day_of_week_name` ∈ {Saturday, Sunday} |
| `easting_bng`, `northing_bng` | Projected OSGB36 metric coordinates |

---

## 7. Orphan Record Removal

Vehicle and casualty records referencing `accident_index` values not present in the cleaned accident table are removed. This enforces referential integrity equivalent to a foreign key constraint.

## 9. Train / Validation / Test Split

For ML model training, the cleaned accidents dataset is split:

| Split | Fraction | Purpose |
|---|---|---|
| Train | 70% | Model fitting |
| Validation | 10% | Hyperparameter tuning |
| Test | 20% | Final evaluation (temporal holdout: 2025 data) |

The test set uses temporal holdout (2025 accidents reserved) to simulate real-world prediction on unseen future data. This prevents data leakage from the time dimension.
